# CONTEXT — Repo Operations

## Purpose

This folder defines how Spark Lab STB uses GitHub, Codex, commits, pull requests, and reference repositories.

The goal is to keep the build environment solid, nimble, and clean while still allowing the project to learn from related repositories and systems.

## Core rule

```text
One active repo. Many reference libraries. Clean promotion only.
```

## Active build repo

```text
MajorDream444/SPARK-LAB-STB
```

This is the source of truth for the Spark Lab STB platform.

## What belongs here

- STB doctrine
- Business Pressure Test routing
- Stop the Bleed webinar assets
- Gumroad lead capture assets
- 7–14 day STB sprint protocols
- 30-Day Continuity OS
- client interface docs
- visual workflows
- operator playbooks
- repo operations

## What does not belong here

- unrelated Mobstack strategy
- raw NotebookLM experiments unless adapted into STB
- full Graphify implementation unless converted into STB visual workflow doctrine
- Shopify store operations unless tied to STB Gumroad/digital product paths
- AI business acquisition or seller-financing doctrine
- unrelated app scaffolds

## Operating posture

STB should stay markdown-first until repeated platform patterns prove what app or automation should be built.

Do not add dependencies, apps, packages, or services unless they directly support the current STB build phase.
