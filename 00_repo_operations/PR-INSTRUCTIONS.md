# Pull Request Instructions

Create draft pull requests by default.

## PR title format

Use conventional style:

`<type>: <short outcome>`

Examples:

- `docs: initialize STB doctrine and repo scaffold`
- `feat: add Stop the Bleed webinar OS`
- `feat: add Gumroad lead capture assets`
- `feat: add visual workflow maps`
- `refactor: simplify client interface rules`

## Required PR description sections

Every PR description should include the sections below.

### 1. Purpose

Explain what this PR adds or changes.

### 2. Active repo

Confirm the target repo is:

`MajorDream444/SPARK-LAB-STB`

### 3. Source material / references

List any referenced repos, docs, or frameworks used.

Examples:

- Mobstack for agent architecture
- Graphify for visual workflow patterns
- NotebookLM for podcast or reassurance workflow
- Flo case study for STB doctrine
- Business Pressure Test notes

### 4. Files changed

Summarize the major folders and files touched.

### 5. STB doctrine check

Answer:

- Does this reduce overwhelm?
- Does this preserve the One-Room Rule?
- Does this keep the client interface peaceful?
- Does this track evidence instead of vibes?
- Does this avoid premature app-building?

### 6. Boundaries check

Confirm:

- No paid ads management was added as a core offer.
- No therapy, medical, legal, or financial claims were added.
- No business acquisition or seller-financing doctrine was mixed into STB core.
- No unrelated reference repo content was copied in without adaptation.

### 7. Review status

Mark what still needs human review before merge.

## Merge method

Default merge method: merge commit is acceptable for now.

## Force push rule

Do not force-push unless explicitly needed.

## Draft PR rule

Keep PRs in draft until the room is coherent and reviewable.
